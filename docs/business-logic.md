# Бизнес-логика · archive-451-cms

> Фичи, пользователи, сущности и зависимости функций. Стиль кода — `docs/tech-specs.md`,
> дизайн — `docs/design.md`.

## Идея продукта

Читательский дневник: пользователь читает множество книг и ведёт свою базу знаний, чтобы
вернуться к конкретной книге и освежить в памяти её основные идеи и сюжет без перечитывания.
Заметки ведутся в формате Markdown, в духе Obsidian. Библиотеку можно показать другим —
поделиться ссылкой на просмотр ограниченному кругу читателей.

**Сценарий:** админка (Payload) — ввод данных (книги, заметки). Фронтенд — «витрина» библиотеки:
сетка книг с фильтрами → страница книги со всеми её заметками.

## Пользователи

| Кто | Что делает | Как |
| --- | ---------- | --- |
| Владелец библиотеки | Вводит книги, обложки, заметки | `/admin` (Payload, коллекция `users`, auth; интерфейс админки — ru по умолчанию, переключается на en) |
| Читатели | Ведут свою библиотеку: книги и заметки видны только им | `/` и `/books/[id]` — после входа через `/auth` (группа `(private)`); язык фронта (ru/en) — в меню пользователя; шеринг ссылки — в дорожной карте |

Библиотеки личные: книга принадлежит создавшему её пользователю (`owner`), заметки наследуют
доступ через книгу. Админ (`role: 'admin'`) видит все книги в `/admin`, на фронте — как обычный
пользователь, только свою библиотеку. Первый зарегистрировавшийся получает мок-библиотеку (см. сев).

| `/books/[id]` | Книга: обложка, мета (статус, оценка, дата, теги), описание, кнопка «Открыть в Яндекс.Книгах», заметки книги (Markdown), wiki-ссылки и обратные ссылки; доступ после входа |

| `/notes`      | Все заметки пользователя с переходами к редактированию; поиск по тексту заметки, заголовку, книге и автору; фильтр по `#тегу` |
| `/notes/new`  | Создание заметки в выбранной книге с Markdown-предпросмотром; при переходе со страницы книги книга выбрана заранее |

## Сущности

### Книга (`books`)

| Поле          | Тип                                   | Примечание       |
| ------------- | ------------------------------------- | ---------------- |
| `title`       | text, required                        |                  |
| `authors`     | relationship → `authors`, hasMany    | нормализованные записи авторов; новые книги ссылаются сюда |
| `author`      | text (legacy)                         | сохранено для совместимости; при миграции вся строка считается одним именем |
| `description` | textarea                              | краткое описание |
| `cover`       | upload → media                        | загруженная обложка; при наличии имеет приоритет над `coverUrl` |
| `coverUrl`    | text                                  | внешняя обложка Open Library (необязательно) |
| `sourceUrl`   | text                                  | ссылка на источник данных, например Open Library или Яндекс.Книги |
| `status`      | select `want`/`reading`/`done`        | default `want`   |
| `rating`      | number 0–10                           | 0 = не оценена   |
| `finishedAt`  | date (sidebar)                        | дата прочтения   |
| `tags`        | array of `tag`: text                  | теги/жанры       |

### Заметка (`notes`, defaultSort `-createdAt`)

`title` (text, required), `book` (relationship → books, required), `content` (textarea «Заметка (Markdown)»).
Заметку можно создать и редактировать из фронтенда; для этого не требуется Payload Admin. Создание
доступно только в собственной книге, редактирование — только для собственной заметки.

### Автор (`authors`)

`name` — отображаемое имя; `nameKey` — уникальный ключ после Unicode NFKC, trim, схлопывания пробелов
и приведения к нижнему регистру. При переносе старая строка `books.author` сохраняется целиком как
одно имя: запятые не используются для предположительного разделения соавторов. Книги постепенно
связываются с записью автора через `books.authors`.

### Шеринг библиотеки (`library-shares`)

На пользователя приходится одна запись: владелец, список книг, активность и SHA-256 хеш секрета.
Секрет генерируется криптографически и показывается только при создании или ротации; в Payload он
не хранится открытым текстом. Публичная страница сначала проверяет активный токен, затем показывает
только выбранные книги владельца с `isPublic: true`. Приватные книги, заметки и сведения о владельце
не выдаются. Сохранение ротирует токен, отзыв сразу закрывает старый URL.

### Прочее

`media`: `alt` (text, required) + upload, `read: () => true`. `users`: auth.
Сгенерированные типы: `src/modules/admin/payload-types.ts`. Второго `payload-types.ts` в корне быть не должно.

Доменные типы (маппинг в `repository/books-repository.ts`): `Book = { id, title, author, description,
coverPath, sourceUrl, status, rating, finishedAt, tags, notesCount }`;
`Note = { id, title, bookId, content, createdAt }`.

### Автозаполнение книги

- `/library/new` ищет по названию, автору или ISBN через документированный Search API Open Library.
- Результат предлагает название, автора, описание, год первого издания, обложку и ссылку на запись.
  Все значения можно проверить и изменить до сохранения.
- Кнопка результата заполняет только пустые поля. Ручной ввод остаётся доступен при пустой выдаче
  или ошибке внешнего сервиса.
- Обложка показывается по URL Covers API Open Library; загруженная в `media` обложка имеет приоритет.
- Поиск Яндекс.Книг через автоматический разбор сайта не используется: в опубликованной документации
  не найден подходящий публичный API, а соглашение сервиса ограничивает копирование и использование
  каталога возможностями самого сервиса.

### Глобальный поиск заметок

`/notes?q=...` ищет без учёта регистра в заголовке и Markdown-тексте заметки, названии книги и
именах авторов. Запрос ограничен 200 символами и всегда исполняется с доступом текущего пользователя
(`user` + `overrideAccess: false`); теговый фильтр можно комбинировать с поиском.

### Хранение media

Payload использует S3 adapter для коллекции `media`, когда заданы `S3_ACCESS_KEY_ID`,
`S3_SECRET_ACCESS_KEY` и `S3_ENDPOINT`; бакет задаётся `S3_IMAGES_BUCKET`. Для локального MinIO
используется path-style S3 endpoint. Перед запуском Next с S3 надо выполнить
`scripts/migrate-media-to-s3.sh` (по умолчанию `.env.development`): файлы копируются в бакет,
локальный каталог `media/` остаётся резервной копией и не удаляется.

## Правила и расчёты (зависимости функций)

- **Статусы**: `want` → «Хочу прочитать», `reading` → «Читаю», `done` → «Прочитана»
  (`BOOK_STATUS_LABELS`). `finishedAt` заполняется только для прочитанных.
- **Рейтинг**: шкала 0–10; `0` = «не оценена» — пилюля рейтинга не показывается, фильтром
  «мин. рейтинг» такие книги **не отсеиваются** (`book.rating > 0` в условии).
- **`notesCount`** считается репозиторием одним запросом notes (Map по `bookId`) — в БД не хранится.
- **Маппинг**: `cover.url → coverPath`; отсутствующие значения → `''` / `0` / `null`; `getBook`
  возвращает `null` при отсутствии (catch NotFound) → compose вызывает `notFound()`.
- **Мок-данные**: при инициализации Payload (`onInit` → `src/modules/admin/seed/mock-books.ts`)
  в **пустую** коллекцию books сеются три книги с разными статусами — «451 градус по Фаренгейту»
  (прочитана), «Мастер и Маргарита» (читаю), «Государство» Платона (хочу прочитать).
  Вместе с книгами создаются заметки: три у «451 градуса» (суть, цитаты, анализ — с таблицей GFM),
  одна у «Мастера и Маргариты», у «Государства» заметок нет.
  Обложки берутся из `media/`: документ media переиспользуется по имени файла, иначе создаётся
  из файла на диске. При перезапусках и при непустой коллекции ничего не создаётся.
  Ручной запуск — `pnpm exec payload run scripts/seed.ts`.

### Фильтрация и сортировка (`domain/book-filters.ts`, `repository/books-repository.ts`)

- Поиск — подстрока без учёта регистра по `title` и `author`; условия выполняются через Payload `contains`.
- Статусы: пусто = все; выбраны — книга подходит при совпадении хотя бы с одним (ИЛИ).
- Теги: пусто = все; книга подходит, если имеет **хотя бы один** из выбранных тегов.
- Рейтинг: порог «от N» применяется только к оценённым книгам.
- Сортировки: `title-asc`, `rating-desc`, `finished-desc` (дата прочтения, отсутствующая = 0),
  `added-desc` (id). Дефолт — `title-asc`; книги без даты и оценки сохраняют положение после
  заполненных значений.
- `countActiveBookFilters`: поиск (0/1) + статусы (1, если выбраны не все) + кол-во выбранных тегов + рейтинг (0/1).
- Пагинация на сервере: размеры страницы 12/24/48; параметры `q`, повторяющиеся `status` и `tag`,
  `rating`, `sort`, `page`, `size` сохраняются в URL. Некорректные значения отбрасываются.
- В UI передаются только выбранная страница, общее число совпадений и общее число книг. Для
  фильтра тегов репозиторий выбирает только поле `tags` из библиотеки, затем показывает уникальные
  отсортированные значения (`collectBookTags`). Счётчики заметок загружаются только для книг страницы.

### Плюрализация (`domain/note.ts`)

«1 заметка» / «2–4 заметки» / «5+ заметок» (`pluralizeNotes`); даты — `ru-RU`.

### Obsidian-ссылки и теги

- `[[Название]]` ищет точное совпадение без учёта регистра среди книг и заметок текущего
  пользователя. Единственное совпадение становится ссылкой на книгу или заметку.
- Отсутствующая или неоднозначная цель отображается исходным текстом `[[Название]]` без ссылки.
  Редактор сохраняет исходный текст.
- Ссылки и `#теги` внутри inline-кода, блоков кода и обычных Markdown-ссылок не обрабатываются.
- Backlinks показывают заметки текущего пользователя, содержащие однозначную wiki-ссылку на
  текущую книгу или заметку; self-link не считается backlink для заметки.
- `#тег` в Markdown отображается ссылкой на `/notes?tag=тег`; список фильтруется только по
  тегам из текста заметок этого пользователя.

### Поиск и публикация библиотеки

- Поиск заметок фильтрует на стороне Payload и сохраняет область доступа владельца; результаты
  остаются на `/notes/[id]` и содержат ссылку на книгу.
- Владелец сам выбирает книги для ссылки. Включить можно только свои книги со статусом публикации;
  при переключении книги в приватную она скрывается со страницы сразу.
- Ссылка — bearer-секрет: передавать её можно только доверенным читателям. Запись хранит только
  SHA-256 хеш; при ротации старый URL становится недействительным, при отзыве страница отвечает 404.
- Публичная страница показывает метаданные книги и обложку, но никогда не возвращает заметки,
  данные аккаунта владельца или приватные книги. `robots` выставлен в `noindex, nofollow`.
- Payload S3 подключается только если заданы все необходимые env-переменные; при миграции
  `mc mirror` копирует файлы без удаления локального источника для возможности отката.
